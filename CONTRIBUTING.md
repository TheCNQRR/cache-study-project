# Процесс разработки (Git Flow)

## 1. Ветки
- `master` — стабильная ветка. Прямой push запрещен.
- `feature/<кратко>` — для новых фич (напр. `feature/add-sms-channel`).
- `fix/<кратко>` — для багфиксов (напр. `fix/login-error`).

## 2. Правила работы
1. Один PR = одна задача.
2. Перед созданием PR сделай `git rebase master`, чтобы подтянуть свежие изменения и избежать конфликтов.
3. Вливаем в `master` только через **Squash Merge**.
4. В `master` **запрещен force-push**.
5. PR должен иметь зеленый CI (status check: `build`), иначе кнопка Merge заблокирована.
